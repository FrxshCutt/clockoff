# Rename audit: Work Mode → ClockOff

The product is renamed from **Work Mode** to **ClockOff**. "Work Mode" stays as the name of the domain concept:
the state an employee’s phone is in while a shift is active (the state machine, `WORKING`, `WORK_MODE_STARTED` /
`WORK_MODE_ENDED`, "WORK MODE ACTIVE", `WorkModeEngine`, `WorkModeController`, `workmode-cases.json`).

This file has two parts. **Part 1** is the inventory taken before any change (2026-10-07). **Part 2** is the
report written after the rename.

## Part 1 — Inventory (before the rename)

Search: `git grep -I -i -E "workmode|work_mode|work-mode|work mode"` over every tracked file: **3,218 matching
lines in 699 files**. Five read-only classifiers each took one area and classified every line against one policy.
Lines that hold only rule-covered identifiers are counted by token group. Every prose occurrence and every
identifier the rules did not cover is listed one by one below.

Outside the five areas (never edited): the shared engine fixtures `docs/fixtures/` and their byte-identical iOS
copy, Prisma migrations (counted in `packages`), `pnpm-lock.yaml` (regenerated by `pnpm install`, never hand-edited),
`docs/dns-backup-*.json` (verbatim exports) and `docs/openapi.json` (generated by `pnpm openapi`; its title is listed
under docs).

### Classes

- **product**: the word names the product, so it becomes ClockOff.
- **concept**: the word names the Work Mode state, so it stays.
- **ambiguous**: it could be read either way, so it stays and is flagged.
- **identifier-rename** / **identifier-keep**: an identifier the standing rules did not cover, with the decision.

### Orchestrator decisions on borderline items

- **O-1 iOS Home screen title.** `HomeView` shows `navigationTitle("Work Mode")` on the app’s home tab. A home tab’s
  title is the app’s name, so it becomes **ClockOff**. The web help entry that names that screen follows it.
- **O-2 Shield fallback title.** `ShieldCopy.defaultTitle` is shown on the shield when the employer’s name is
  unknown. It is a brand label, so it becomes **ClockOff**, along with the web shield preview’s label and the doc that
  quotes it. The shield subtitle "Work Mode is active until HH:mm" is the concept and stays.
- **O-3 System actor.** Where the platform itself is the actor in activity feeds and the How it works flow, it is
  the product (ClockOff).
- **O-4 Historical records stay as written.** Decision log entries D-001 to D-020 and the dated 2026-10-05 repository audit stay as
  written; the rename is recorded as a new decision. Dated observations of the live site in `DEPLOYMENT.md` /
  `DNS_RECORDS.md` are re-observed after the renamed build is deployed.
- **O-5 Out of scope, flagged only.** The shared privacy principle reads "Block distractions. Don’t spy on
  employees." while the marketing site and `config/site.ts` already say "Don’t monitor employees." No "Work Mode"
  is involved, and an iOS parity test pins the shared line, so it was not changed.

Why `online.clockoff.app` and not `com.clockoff.app`: Apple bundle ids are reverse-DNS names, the domain the
owner controls is `clockoff.online`, and a `com.clockoff.*` id may already be registered by another developer,
which would make the App ID registration fail. To use `com.clockoff.app` instead, change the five ids and the
App Group in `apps/ios/Config/Signing.xcconfig`, `project.yml` (`bundleIdPrefix` and the four
`application-groups` entries), `WorkModeCore` `AppGroup.identifier`, `Scripts/verify-release.sh`, and the other
strings in the table, then run `make generate`.

**The App Group is identical in all four targets.** Checked explicitly:

- the four entitlements files (`ClockOffApp`, `ClockOffDeviceActivityMonitor`, `ClockOffShieldConfiguration`,
  `ClockOffShieldAction`), `Config/Signing.xcconfig`, `project.yml` (4 entries), `WorkModeCore`
  `AppGroup.identifier` and `Scripts/verify-release.sh`: all `group.online.clockoff.app.shared`;
- the entitlements embedded in all four binaries of a signed simulator build: all
  `group.online.clockoff.app.shared`;
- `make build-release` with `verify-release.sh`: "4 targets with correct bundle ids, App Group and Family Controls,
  3 extensions embedded";
- no `group.com.workmode` string remains anywhere except where the decision log and this audit quote the old value.

DeviceActivity names never contained the product name (`shift-<id>-v<n>` and `break-<id>-…`), so none changed.
Keychain services and App Group contents moved with the new identifiers, so an existing install would lose its
tokens and cached schedule and have to join again; there are no production installs, so nothing is lost.
