# Environment Variables

All configuration comes from environment variables. Locally they live in a single root `.env`
(`pnpm setup:env` creates it from `.env.example` with generated secrets). Package scripts load it with
`dotenv -e ../../.env`. In production they are Railway service variables (`docs/DEPLOYMENT.md` › Environment
variables); never commit a real `.env`. `apps/web/.env.production.example` gives example production values with
notes only. The authoritative list of names production sets is `.railway/railway.ts` (below): a name not listed
there must not be set on Railway until it is added. Where the template disagrees (its header suggests Railway
shared variables and says Railway provides `PORT`, and it gives values for names production leaves unset), this
page and `.railway/railway.ts` are right.

`apps/web/src/lib/env.ts` validates everything at first use with Zod and fails fast with a clear message. The web
process and the worker validate the **same** schema, so a variable both read must hold the same value in both.

## Where each variable is set in production (Railway)

| Service            | Variables                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `web` and `worker` | `APP_URL`, `CLIENT_IP_HEADER`, `DATABASE_URL`, `DEV_TOOLS_ENABLED`, `DIRECT_URL`, `EMAIL_FROM`, `EMAIL_PROVIDER`, `HOST_ROUTING`, `INTEGRATION_ENCRYPTION_KEY`, `LOG_LEVEL`, `MARKETING_URL`, `MOBILE_JWT_KEY_ID`, `MOBILE_JWT_SECRET`, `NEXT_PUBLIC_APP_URL`, `NEXT_TELEMETRY_DISABLED`, `PLANDAY_CLOCK_MODE_ENABLED`, `PLANDAY_ENABLED`, `PLANDAY_MODE`, `RATE_LIMIT_BACKEND`, `RESEND_API_KEY`, `SESSION_SECRET`, `SESSION_TTL_DAYS`, `SHUTDOWN_GRACE_MS`, `TEST_TOOLS_ORGANISATION_IDS`, `TRUSTED_PROXY_HOPS` |
| `web` only         | `PLANDAY_APP_ID`, `PLANDAY_CLIENT_ID`, `PLANDAY_OAUTH_PKCE`, `PORT` (`8080`), `REALTIME_STREAM_MAX_LIFETIME_MS`                                                                                                                                                                                                                                                                                                                                                                                                   |
| `worker` only      | `WORKER_JOBS_ENABLED`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `www`              | `REDIRECT_TO` (`https://clockoff.online`), `PORT` (`8080`); both set in `.railway/railway.ts`                                                                                                                                                                                                                                                                                                                                                                                                                     |

These lists are the `SHARED_VARIABLES`, `WEB_VARIABLES` and `WORKER_VARIABLES` constants in `.railway/railway.ts`.
Every name there is kept by `preserve()`; a variable **missing** from them is deleted by the next
`railway config apply`, so add a new name to the file in the same change that starts reading it (the
`WEB_VARIABLES` list and the `WORKER_VARIABLES` line are pinned by `apps/web/src/deploy/railwayConfig.test.ts`,
so update its expected values too: `docs/DEPLOYMENT.md` › Configuration as code; the same test checks that every
`PLANDAY_*` variable `env.ts` reads, except the development-only `PLANDAY_MOCK_URL`, is listed). Variables not
listed (APNs, `NEXT_PUBLIC_APP_STORE_URL`, the token lifetimes, `REQUIRE_EMAIL_VERIFICATION`, …) are unset in
production and take their defaults.

Railway also injects `RAILWAY_*` variables into every deployment. The app reads `RAILWAY_REPLICA_ID`,
`RAILWAY_SERVICE_NAME` and `RAILWAY_GIT_COMMIT_SHA` (worker heartbeat identity, LISTEN session name) and
`RAILWAY_ENVIRONMENT_ID` / `RAILWAY_PROJECT_ID` / `RAILWAY_ENVIRONMENT_NAME` (to detect Railway for the
`CLIENT_IP_HEADER` check). Never set them yourself.

## Retired variables

| Variable       | Was                                                                                                         | Now                                                                                                                                                                                                                              |
| -------------- | ----------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `JOBS_ENABLED` | Netlify era: `false` on the web app meant "the scheduled function runs the tick, not the in-process runner" | Never a switch. `env()` warns while it is set, and the worker **refuses to start while it is `false`**, so a value copied from the old site cannot silently stop every job. Remove it; `WORKER_JOBS_ENABLED` is the kill switch. |
| `CRON_SECRET`  | Bearer secret for `POST /api/jobs/tick`, which the Netlify Scheduled Function called every minute           | The route is deleted (the worker runs the jobs). `env()` warns while it is set. Remove it.                                                                                                                                       |

Neither is set on Railway, and `.railway/railway.ts` must never list them (`railwayConfig.test.ts` checks).

## Generating secrets

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"     # SESSION_SECRET / MOBILE_JWT_SECRET
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"  # INTEGRATION_ENCRYPTION_KEY
```
